# 控制台 UI 设计纲要

> 日期：2026-08-09 · 状态：方向纲要（高保真 mockup 为下一步交付物，评审通过后才写
> spec-1.13/1.14）· 用户要求：参考业界知名产品交互经验，设计美观，编码前完成 UI 设计。

## 1. 参考产品与借鉴点

| 产品 | 借鉴什么 | 不借鉴什么 |
|---|---|---|
| **Datadog** | 监控信息密度控制、实例列表→详情下钻路径、时间范围选择器交互 | 视觉过载的仪表盘堆叠 |
| **Grafana** | 图表交互（hover 联动、区间缩放）、告警状态色语义 | 面板配置复杂度 |
| **Supabase / PlanetScale** | 现代 DB SaaS 视觉气质：克制的深色主题、清晰的层级、优秀的空状态与接入引导 | — |
| **Claude / ChatGPT** | 诊断对话界面：流式输出、工具调用过程可视化（"正在分析慢日志…"）、引用数据溯源 | — |
| **Linear** | 交互品质基准：键盘优先、列表性能、命令面板（Cmd+K） | — |

## 2. 信息架构（11 个板块，对话为核心工作台）

```
对话 Workspace ─ 通用对话工作台（核心页面 + 登录默认落地页，见 §3）：
│               诊断 / 知识库问答 / 迁移等长任务全部在同一对话窗口展开
任务 Tasks ─ 定时与长任务面板（2026-08-09 user 新增）：任务列表（类型/执行
│           Agent/调度/上次结果/下次运行）、任务详情与运行历史、今日运行记录。
│           **概念模型（本次评审定）**：任务 = 工作定义（目标 + 调度 + skill +
│           结果去向），Agent = 长期身份（实例绑定 + 记忆 + 权限）；任务在对话中
│           创建，由目标实例的**负责 Agent** 执行，不为任务单独创建 Agent——
│           避免记忆归属分裂与权限重复建设（运行时本就是无状态共享 Pod 池，
│           AD-1，"常驻/独立 agent"在进程层无区别）；目标实例无负责 Agent 时，
│           创建流程引导先建 Agent。三类任务：一次性 / 定时巡检 / 长任务 Job
总览 Dashboard ─ 租户健康大盘：实例状态分布、未读巡检结论、告警流、用量概览
├─ 数据库 ─ 单模块双视图（2026-08-09 user 定：原"数据源"+"拓扑"合并，避免平级重叠）
│   ├─ 列表视图 ─ Connector 状态卡 + 实例可过滤表格（协议族/引擎、健康分、
│   │             最近巡检、QPS 迷你图）+ 接入向导入口
│   ├─ 拓扑视图 ─ 主备/集群复制关系连线（含复制方式与延迟）、按负责 Agent 分组
│   │             的管理域、健康态着色、拓扑级风险提示；单击节点 = 页内下钻面板，
│   │             面板按钮/双击 = 进实例详情
│   └─ 实例详情 ─ 指标时间线、慢查询、巡检历史、该实例的对话入口
├─ 巡检中心 ─ 巡检策略配置、报告列表 → 报告详情（结论分级 + 证据下钻 + 一键转对话）
├─ 平台大盘 ─ AIRush 自身运行拓扑（平台运营角色可见，租户不可见；2026-08-09
│             user 新增）：K8s 集群资源规模（节点/vCPU/内存/Pod/GPU）、
│             工作负载池（接入网关、控制台 API、LLM 网关、agent-runtime、
│             记忆服务、embedding、skill 容器，含副本数与扩缩策略）、
│             托管存储架构（PG/threadstore、TimescaleDB、Neo4j、pgvector、
│             Redis，含容灾角标）、客户侧 Connector 与外部模型、关键数据流连线
├─ Agent 管理 ─ agent 配置：绑定实例、挂载 skill、巡检策略、记忆概览
├─ 审批中心 ─ 动作类操作待审批队列 + 审批历史（AD-9）
├─ 审计日志 ─ 全链路事件检索
└─ 设置 ─ 租户/成员/RBAC、LLM 用量与配额、脱敏规则
```

**原则（2026-08-09 user 定）：chat-first，不是 chat-only**——对话是"干活的地方"，
管理页面是"看全局与管控的地方"，两侧互相深链（巡检异常"转对话"、对话产出动作
进入审批中心）。审批的权威队列必须留在审批中心（AD-9 硬约束），对话内的审批卡
只是发起/查看入口。

## 3. 核心页面：通用对话工作台的关键交互

> 2026-08-09 由"诊断对话"升级为通用工作台（user 定）：会话按类型组织
> （诊断 / 问答 / 任务），知识库问答、数据迁移、表结构评审等能力以 skill 形式
> 接入同一窗口——依托"声明式内容块 + 渲染器注册表"（spec-1.9 定块协议、
> spec-1.14 实现渲染器），新增能力 = 新 skill（+ 必要时新块类型），界面零改造。
> UI 形态对齐 agent 运行时的 thread/turn 模型（AD-11 codexgo 抽核），无转换损耗。

1. **过程透明**：agent 调用 skill/取数时展示可折叠的步骤卡（"查询近 24h 慢日志 →
   聚类 37 条 → 调用慢查询分析"），完成后折叠为一行摘要——借鉴 Claude 工具调用可视化；
2. **证据溯源**：结论中的数据引用可点击，侧栏打开对应指标图表/慢日志原文（脱敏后）；
3. **图文混排**：回答内嵌迷你图表（指标趋势、对比），非纯文本墙；
4. **动作即审批**：agent 建议的动作类操作渲染为审批卡片（操作内容、影响面、风险级），
   点击进入审批流，绝不静默执行；
5. **会话上下文**：左侧会话列表按类型分组（诊断 / 任务 / 问答），支持从巡检报告
   /实例详情"带上下文开启对话"；
6. **长任务形态**：迁移类 Job 型 skill 在对话中发起后转 Connector 侧后台执行
   （对应 skill-runtime-design 的 Job 型 skill），进度事件流回填对话（阶段
   checklist + 进度条内容块），人可离开再回来，完成后推送通知并交付产物
   （如迁移校验报告）；其中动作类步骤（如流量切换）仍走审批（AD-9）；
7. **会话路由**（2026-08-09 user 定）：开场无法判定目标库时由租户内置**助理
   Agent** 接待——四路定位（入口上下文 / 业务别名映射 / 租户记忆检索 / 候选
   chip 让用户点选），定位后同会话移交负责 Agent（multiagent）；知识库问答与
   跨库比较类问题助理自答不移交；路由步骤在对话中以步骤卡可见（过程透明）。
   详见 agent-core-design §2.1。

## 4. 设计语言方向

- **基调**：专业运维工具的克制感——低饱和深色主题为默认（DBA 值班场景），提供浅色；
  数据密度中高，但用留白与层级避免 Datadog 式过载；
- **色彩语义**：状态色全局唯一（健康绿/警告琥珀/严重红/未知灰），图表用色遵循
  可访问性对比（色盲安全调色板）；品牌主色待定（mockup 阶段给 2-3 方案）；
- **排版**：数字与代码等宽字体（指标、SQL）；中文正文字体优先系统栈；
- **组件基底**：shadcn/ui + Tailwind（自持代码、可深度定制、无重型依赖），图表 ECharts
  （国内生态、大数据量性能）——mockup 评审后在 spec-1.13 定版。
