# 控制台 UI 设计纲要

> 日期：2026-08-09 · 状态：方向纲要（高保真 mockup 为下一步交付物，评审通过后才写
> spec-1.13/1.14）· 用户要求：参考业界知名产品交互经验，设计美观，编码前完成 UI 设计。

## 1. 参考产品与借鉴点

| 产品 | 借鉴什么 | 不借鉴什么 |
|---|---|---|
| **Datadog** | 监控信息密度控制、实例列表→详情下钻路径、时间范围选择器交互 | 视觉过载的仪表盘堆叠 |
| **Grafana** | 图表交互（hover 联动、区间缩放）、告警状态色语义 | 面板配置复杂度 |
| **Supabase / PlanetScale** | 现代 DB SaaS 视觉气质：克制的深色主题、清晰的层级、优秀的空状态与接入引导 | — |
| **Claude / ChatGPT** | 诊断对话界面：流式输出、工具调用过程可视化（"正在分析慢日志…"）、引用数据溯源 | — |
| **Linear** | 交互品质基准：键盘优先、列表性能、命令面板（Cmd+K） | — |

## 2. 信息架构（8 个关键页面）

```
总览 Dashboard ─ 租户健康大盘：实例状态分布、未读巡检结论、告警流、用量概览
├─ 数据源管理 ─ Connector 状态 + 实例列表（协议族/引擎标识、健康分、最近巡检）
│   └─ 实例详情 ─ 指标时间线、慢查询、巡检历史、该实例的诊断会话入口
├─ 巡检中心 ─ 巡检策略配置、报告列表 → 报告详情（结论分级 + 证据下钻 + 一键转诊断）
├─ 诊断对话 ─ 会话式界面（核心页面，见 §3）
├─ Agent 管理 ─ agent 配置：绑定实例、挂载 skill、巡检策略、记忆概览
├─ 审批中心 ─ 动作类操作待审批队列 + 审批历史（AD-9）
├─ 审计日志 ─ 全链路事件检索
└─ 设置 ─ 租户/成员/RBAC、LLM 用量与配额、脱敏规则
```

## 3. 核心页面：诊断对话的关键交互

1. **过程透明**：agent 调用 skill/取数时展示可折叠的步骤卡（"查询近 24h 慢日志 →
   聚类 37 条 → 调用慢查询分析"），完成后折叠为一行摘要——借鉴 Claude 工具调用可视化；
2. **证据溯源**：结论中的数据引用可点击，侧栏打开对应指标图表/慢日志原文（脱敏后）；
3. **图文混排**：回答内嵌迷你图表（指标趋势、对比），非纯文本墙；
4. **动作即审批**：agent 建议的动作类操作渲染为审批卡片（操作内容、影响面、风险级），
   点击进入审批流，绝不静默执行；
5. **会话上下文**：左侧会话列表按实例/主题分组，支持从巡检报告"带上下文开启诊断"。

## 4. 设计语言方向

- **基调**：专业运维工具的克制感——低饱和深色主题为默认（DBA 值班场景），提供浅色；
  数据密度中高，但用留白与层级避免 Datadog 式过载；
- **色彩语义**：状态色全局唯一（健康绿/警告琥珀/严重红/未知灰），图表用色遵循
  可访问性对比（色盲安全调色板）；品牌主色待定（mockup 阶段给 2-3 方案）；
- **排版**：数字与代码等宽字体（指标、SQL）；中文正文字体优先系统栈；
- **组件基底**：shadcn/ui + Tailwind（自持代码、可深度定制、无重型依赖），图表 ECharts
  （国内生态、大数据量性能）——mockup 评审后在 spec-1.13 定版。

## 5. 交付路径（编码前完成）

1. 本纲要 user 评审 → 方向修正；
2. **高保真 HTML mockup**：先做 4 个页面（总览、实例详情、巡检报告、诊断对话），
   2-3 套视觉方案供选；
3. mockup 评审定稿 → 沉淀《UI 设计规范》（色板/字阶/间距/组件清单）；
4. 规范作为 spec-1.13/1.14 的 §2 接口设计输入，前端开发照稿实现。
