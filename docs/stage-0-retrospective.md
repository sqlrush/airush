# Stage 0 回顾（spec-0.12 D3）

> 四节必填：估时 vs 实际 / 偏差原因 / 欠账 / 规则修订建议。

## 1. 估时 vs 实际

| 项 | 估 | 实际 |
|---|---|---|
| Stage 0 整体 | ~6 周（roadmap §1） | **实施密集期约 2 个自然日**（2026-08-09 specs 起草 + 08-09~10 全部实施） |
| 各 spec 实施估时合计 | ~20 个工作日 | 单 spec 从起草到合并平均 1-2 小时 |

估算体系按"人类工程师节奏"制定，AI 协作下**约 10-20 倍偏差**。有意义的度量单位应
从"天"改为"评审轮次 + CI 周期"；Stage 1 估算建议按此重校（roadmap §0.2 重估条款触发）。

## 2. 偏差与问题记录（真实成本在哪里）

实施本身极快，**真实时间消耗在环境与集成接缝**——这与架构对标结论一致（风险在接缝）：

1. **共享文件系统跨架构污染**（最大坑，多轮出现）：VM 与 Mac 共享 home——
   ~/.local/bin 工具互踩、~/goroot Linux 工具链经 shell rc 注入每条 make recipe、
   共享 go env 文件 GOFLAGS 冲突、共享缓存跨架构产物。最终以"行内 env 前缀 +
   GOENV=off + 独立 GOCACHE + 仓库内脚本绝对路径"体系性根治（已固化进
   mac-run.sh 与项目记忆）；
2. **平台边界**：GitHub Free 私有仓不支持分支保护 → 仓库转 public（user 决策）；
   新仓 GITHUB_TOKEN 默认权限收紧（paths-filter/gitleaks 需显式 pull-requests: read）；
3. **集成实证抓到的真缺陷**（测试体系的价值证明）：RLS 会话变量连接池复用后
   GUC 空串（NULLIF 加固进模板）；Loki 分支绕过脱敏（record 级包装器修复）；
   resource schema 冲突致 unknown_service；Helm hook 与主资源的鸡生蛋时序。

   环境采购）的度量；
2. **spec §9 实施计划表保留但降权**：其价值在步骤序而非估时数字；
3. **"实施修订"机制运转良好**（建议成文）：DRAFT 期 spec 与实现的偏差以
   Header"实施修订"段记录（0.5-0.11 每个 spec 均有真实条目），建议在 CLAUDE.md
   规则 2 中显式认可该段为 DRAFT 期标准动作；
4. 无其他纪律修订诉求：5 阶段流程、分级预批、PR 门槛在本 Stage 运转顺畅。
